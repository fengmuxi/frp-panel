# 邮件通知

frp-panel 支持在节点、隧道和账号发生关键事件时发送邮件提醒，并提供三层配置粒度：**SMTP 服务器（全局）→ 用户全局开关（每人一套）→ 资源级三段式（每个节点/隧道单独控制）**。

## 功能入口

| 入口 | 位置 | 说明 |
| --- | --- | --- |
| 邮件通知设置页 | 左下角用户头像 → **邮件通知** | SMTP 服务器配置（仅管理员）+ 通知开关（所有用户） |
| 资源级设置 | 客户端 / 服务端列表的操作菜单、隧道的「···」操作菜单 → **通知提醒设置** | 三段式：不提醒 / 全局配置 / 独立配置 |

> 左下角下拉菜单中的 **邮件通知** 入口对所有登录用户可见；**SMTP 服务器配置** 卡片仅管理员可见可改。

## 一、SMTP 服务器配置（仅管理员）

在「邮件通知」页顶部的 **SMTP 服务器配置** 卡片中填写：

| 字段 | 说明 |
| --- | --- |
| SMTP 服务器 | 邮件服务器域名，如 `smtp.example.com` |
| 端口 | 常见端口：SSL/TLS `465`、STARTTLS `587`、不加密 `25`（选择加密方式时若当前端口是常见端口会自动联动） |
| 加密方式 | **SSL/TLS**（隐式加密，通常 465）/ **STARTTLS**（通常 587）/ **不加密**（通常 25） |
| 账号 / 密码 | SMTP 登录凭据；密码**留空表示不修改**已保存的密码，且加密存储、任何接口都不会回传 |
| 发件人地址 | 邮件 From 地址，必填，如 `noreply@example.com` |
| 发件人名称 | 可选，收件方显示为 `名称 <发件人地址>`，支持中文 |

操作：

1. 点击 **发送测试邮件**：使用当前表单（未保存亦可）的配置发送一封通用测试邮件，收件人为当前登录用户；成功/失败原因会以提示消息返回。
2. 确认无误后点击 **保存更改**，在确认对话框中点 **确认**。

::: tip
所有通知邮件都使用这份全局 SMTP 配置发送。管理员未配置 SMTP（或测试邮件失败）时，任何通知都不会发出。
:::

## 二、用户全局通知开关（所有用户）

同一页面下方的 **邮件通知设置** 卡片，**仅对你自己的账号生效**，默认全部关闭：

**提醒开关（9 项）**

- 服务端掉线提醒 / 服务端上线提醒
- 客户端掉线提醒 / 客户端上线提醒
- 隧道掉线提醒 / 隧道上线提醒
- 隧道流量超额关闭提醒（流量达到限额被自动关闭时）
- 隧道定时开关提醒（按定时规则自动开启或关闭时）
- 用户登录通知（你的账号登录成功后发给你本人）

**下线通知防抖时长**：服务端 / 客户端 / 隧道三类可分别设置（默认 60 秒，可选 30 秒 ~ 10 分钟）。离线**持续超过**所选时长才发送提醒，网络闪断快速恢复不会打扰。

**测试**：每个开关行右侧都有 **测试** 按钮，会用已保存的 SMTP 配置给**你自己**发送一封该类型的样例邮件（用于验证模板与投递，不受开关状态影响）；卡片底部的 **发送测试邮件** 为通用连通性测试。

点击 **保存更改** 后配置立即生效。

## 三、资源级三段式设置

打开任一资源的操作菜单 → **通知提醒设置**，顶部是三个并排按钮：

| 选项 | 行为 |
| --- | --- |
| **不提醒** | 最高优先级：该资源的**所有**提醒（掉线、上线、超额、定时）一律不发送，与全局开关无关 |
| **全局配置**（默认） | 跟随本页「邮件通知设置」中的全局开关；弹窗内会以只读列表展示当前全局开关的开/关状态，便于判断是否需要单独覆盖 |
| **独立配置** | 按该资源自己的一套开关执行，**优先于全局设置** |

- **服务端 / 客户端**的独立配置项：掉线提醒、上线提醒、掉线防抖时长。
- **隧道**的独立配置项：掉线提醒、上线提醒、隧道流量超额关闭提醒、隧道定时开关提醒、掉线防抖时长。
- 选「独立配置」后**未列出**的提醒项不会发送（例如只勾了上线，则掉线不发）。
- 独立配置的防抖时长选「默认」时为内置 60 秒（不是"不防抖"）。

点击 **保存** 生效；三段式选择与独立开关在重新打开弹窗时会回显上次保存的值。

## 四、优先级与生效规则

```
资源级 = 不提醒        → 该资源所有邮件都不发（最高优先）
资源级 = 独立配置      → 按该资源自己的开关与防抖时长
资源级 = 全局配置/未设置 → 按所属用户的全局通知开关
                              （用户从未保存过 → 沿用历史全局默认）
```

**收件人规则**：

- 服务端 / 客户端 / 隧道的掉线、上线、超额、定时邮件 → 发给**该资源所属用户**的邮箱（多用户场景下各发各的，不会串发）
- 登录通知 → 发给**登录者本人**
- 测试邮件 → 发给**当前登录用户本人**

::: warning
收件人的邮箱取自账号资料中的 Email；账号邮箱为空时该账号不会收到任何通知（日志中会记录跳过原因）。
:::

## 五、通知触发时机速查

| 通知 | 触发时机 | 说明 |
| --- | --- | --- |
| 服务端/客户端掉线 | 与 Master 的连接断开后，持续离线达到防抖时长 | 断开期间重连则不发 |
| 服务端/客户端上线 | 节点重新注册成功 | 60 秒内重复注册只发一次 |
| 隧道掉线 | frps 推送的活跃列表中该隧道消失并持续达到防抖时长 | 与服务端断连（推送停止）不判定，由服务端掉线邮件覆盖 |
| 隧道上线 | 曾发出掉线提醒的隧道恢复运行时 | 与掉线提醒配对补发 |
| 流量超额关闭 | 隧道用量达到限额被自动关闭时 | 邮件含限额周期、统计方向、限额与已用流量 |
| 定时开关 | 隧道按定时规则自动开启或关闭时 | 仅启用了定时开关的隧道 |
| 用户登录 | 登录成功后 | 含用户名、登录 IP、时间 |

手动停止隧道 / 停止节点属于主动操作，**不会**触发掉线提醒。

## 六、常见问题排查

1. **一封邮件都没收到**
   - 先用「发送测试邮件」验证 SMTP；失败时按提示修正服务器/端口/加密/账号密码。
   - 确认对应通知开关已开启并保存（默认全部关闭）。
   - 确认收件账号的 Email 非空。
2. **某类提醒收不到**
   - 检查该资源是否被设为「不提醒」，或「独立配置」里没勾选该项。
   - 防抖时长未到（默认 60 秒，隧道约需 2 轮推送即约 1 分钟）。
   - 该事件是手动操作（手动停止/启动不会触发掉线提醒）。
3. **弹窗里的全局预览与邮件通知页不一致**
   - 全局预览为只读展示，修改请到「邮件通知设置」卡片保存。
4. **换了 SMTP 服务器后收不到**
   - 修改后需点「保存更改」，并发送测试邮件确认新配置可用。
